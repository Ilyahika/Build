# Viva Fishing 3.1 — Уровни рыбака

Продолжение работающего **Viva Fishing 3.0**. Сохранены существующие экран рыбалки, 20 рыб, 5 локаций, рюкзак, снасти, 4 бесплатных кейса, онлайн-админка и режим техработ. Вся новая логика — на Python / SQLite3, а не в локальном JavaScript.

## Как обновить работающий Render

1. Сохрани текущий рабочий коммит GitHub на случай возврата.
2. Распакуй ZIP и загрузи **файлы из архива в корень того же GitHub-репозитория**, заменив старые. Папку добавлять не нужно. Обязательные для обновления: `fishing.py`, `fishing_ui.js`, `db.py`, `style.css`, `index.html`, `main.py`, `admin.py`, `admin.js` и остальные файлы проекта.
3. Нажми **Commit changes**. Render автоматически обновится, если включён Auto-Deploy, или вручную нажми **Manual Deploy → Deploy latest commit**.
4. На Render по-прежнему используются те же команды:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1`
5. В Environment **сохрани действующие `BOT_TOKEN` и адрес сервиса**. Админ имеет Telegram ID `1181838335`, как и раньше. Не вставляй токен в GitHub.
6. Проверь `https://ТВОЙ-СЕРВИС.onrender.com/health` и `/health/db`, затем **полностью закрой Mini App** и открой через новую кнопку `/start → Открыть` в Telegram.

**Важно:** бесплатный Render использует временный диск: при новом развёртывании старый `database.db` может пропасть независимо от того, обновлялся ли код. Если используешь существующую постоянную SQLite3, миграция добавит только колонку `fishing_progress.xp_total` и таблицу `fishing_cast_log`, не удаляя уловы, снасти или балансы. Для реальных игроков потребуется постоянная БД/диск. **Данные существующих уловов не превращаются в EXP задним числом:** опыт зарабатывается новыми уловами и открытиями кейсов.

## Локации и уровни

Уровень рыбака — отдельный от уровня дома. Доступ проверяется в Python API, поэтому его нельзя обойти кнопками или изменением JavaScript.

| Локация | Минимальный уровень рыбака |
|---|---:|
| 🌿 Пруд | 1 |
| 🏞️ Озеро | 5 |
| 🌅 Море | 10 |
| 🌊 Океан | 15 |
| ✨ Секретный ручей | 20 |

Закрытые локации показывают значок 🔒 и нужный уровень.

## EXP и сложность прокачки

Для перехода с уровня `N` на уровень `N+1` требуется `80 + 30×(N−1) + 6×(N−1)²` EXP.

Начало: 80, 116, 164, 224, 296, ... EXP за следующий уровень. Шкала показывает текущий уровень, полученный EXP, нужное количество и прогресс.

**За каждую пойманную рыбу** (в зависимости от редкости):

| Редкость | Награда |
|---|---:|
| Обычная | +20 EXP |
| Редкая | +35 EXP |
| Эпическая | +60 EXP |
| Морская | +85 EXP |
| Секретная | +140 EXP |

**За открытие бесплатных кейсов:**

| Кейс | Награда |
|---|---:|
| Береговой | +50 EXP |
| Озёрный | +110 EXP |
| Морской | +240 EXP |
| Тайный | +450 EXP |

EXP начисляется автоматически сервером, сохраняется в SQLite3 и сразу отображается в Mini App. Продажа рыбы не отнимает полученный EXP.

## 10 забросов за 10 минут

- У обычных игроков не больше **10 бесплатных забросов за любые скользящие 10 минут**. Это не сброс всех 10 попыток одновременно: каждая попытка освобождается через 10 минут после собственного использования.
- На экране показаны остаток `10/10`, прогресс-бар и обратный отсчёт до следующей свободной попытки. При появлении новой попытки экран запрашивает актуальный статус автоматически.
- Для защиты от случайных двойных кликов оставлена пауза 4 секунды между забросами.
- Администратор `1181838335` не ограничен по числу забросов, однако закрытые локации для него также требуют соответствующего уровня рыбака.
- Проверка лимита и списание попытки выполняются **в одной транзакции SQLite**, поэтому параллельные клики не дают дополнительные попытки.

## Изменённые файлы

- `fishing.py`: EXP, уровни, блокировка локаций и 10-минутное окно попыток.
- `fishing_ui.js`: полоса EXP, 🔒, счётчик и таймер забросов, награды EXP за рыбу и кейсы.
- `db.py`: безопасная миграция и таблица истории забросов.
- `style.css`: оформление новых элементов.
- `admin.py`, `admin.js`: EXP игрока в карточке, суммарный EXP в статистике, сброс также очищает историю попыток.
- `index.html`: обновлённая версия CSS/JS для сброса кеша Telegram.
- `main.py`: `/health/db` проверяет также новую таблицу.

Нет новых зависимостей и не требуется менять `requirements.txt`.
